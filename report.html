Executive Summary

This report presents a technical and conceptual comparison between the existing Securade.ai HUB (hub-main) project and the newly proposed PRAHARI AI Vision Safety & Risk Intelligence architecture.

While hub-main operates as a reactive, edge-based computer vision tool primarily capturing basic PPE compliance via 2D bounding boxes, PRAHARI introduces a proactive, spatial risk intelligence paradigm. PRAHARI expands the scope beyond basic compliance to include comprehensive workforce resource monitoring, spatial metric awareness (e.g., precise edge distance tracking, dynamic load evaluation on scaffolds), multi-layered dashboards, and deep ecosystem integrations (LMS, domain models).

1. Core Paradigm & Philosophy

Securade HUB (hub-main)

Paradigm: Reactive Compliance

  • Acts as a standalone edge node connecting to RTSP streams.
  • Detects discrete, point-in-time violations (e.g., missing helmet).
  • Notifies via Telegram bots and saves static JPEGs.
  • Simple dashboards summarizing daily occurrence counts.

PRAHARI Architecture

Paradigm: Proactive Risk & Resource Intelligence

  • Analyzes risk dynamically with multi-camera spatial tracking.
  • Predicts near-misses (e.g., dwell time near an unprotected slab edge).
  • Consolidates safety analytics with site productivity/resource monitoring (people, scaffolds, MEWPs).
  • Replays incidents with context and provides actionable EHS recommendations.

3. System Architecture Evolution

Current Architecture (hub-main)

Built as a monolithic Python orchestration layer (securade.py) integrating YOLOv7 inference (OpenVINO/CUDA) and Streamlit/Dash local web apps. It relies on a simplistic plugin system (plugins/base_plugin.py) and local JSON configs. Does not integrate with broader enterprise safety ecosystems.

Target Architecture (PRAHARI)

Designed as an enterprise-grade, layered platform:

  • Vision Engine (Tvashta Core): Offloads raw object detection, spatial mapping, and track-lets to a dedicated vision microservice.
  • Intelligence Layer (PRAHARI): Houses the domain-specific business logic—the 6 Safety Check Families.
  • Risk Engine: Processes data streams for rule execution and anomaly detection.
  • Integrations Layer: Hooks directly into Vasudhava (LMS for training), Laya (Data domains), and Vishva3D (Digital Twins).

5. Conclusion & Recommendations

The hub-main repository serves as an effective foundation for edge-based computer vision ingestion and basic model inference. However, realizing the PRAHARI vision requires a substantial architectural shift.

To bridge the gap, the development team must upgrade the CV pipeline from 2D frame-level analysis to temporal, spatial 3D-aware tracking. Furthermore, the dashboard and alerting systems must evolve from simple static snapshots to comprehensive, interactive risk intelligence interfaces complete with video replay and ecosystem API integrations.
